# Ibid add-in status

## Product direction
Ibid is an EU-law Word add-in for lawyers. It identifies references in footnotes and presents official source material from CJEU/CURIA, EUR-Lex, and European Commission registers inside the task pane. It assists source inspection; it does not assess legal correctness.

## Current implementation
- Individual Word footnotes are read and presented as review items.
- EU-first recognition covers ECLI identifiers, CJEU/General Court case numbers, EU directives, regulations, recommendations, published EU decisions, DG Competition's own case numbers (`AT.`/`SA.`/`M.`), and Treaty articles (`Article 101 TFEU`, `Article 6(3) TEU`, `Article 47 of the Charter`, including the French `TFUE`/`TUE`/`Charte des droits fondamentaux` and `CFR`/`CDFUE` short forms). Legislation is recognised in both the pre-2015 citation style (`Directive 2002/58/EC`, `Regulation (EC) No 1049/2001`) and the current style (`Regulation (EU) 2016/679`, or informally without the bracket), including the number-order reversal between conventions. Article/point locators are recognised from common abbreviations and symbols too (`Art.`, `para.`/`paras.`, `§`, `¶`), not just the spelled-out words, and a paragraph within an article (`Art. 8(5)`) is distinguished from the article as a whole.
- Short-form citations are resolved against the document, not looked up in isolation. A footnote reading only `Akzo Nobel, para. 40` carries no information on its own — it only means anything relative to a full citation stated earlier — so Ibid reads the whole document in order, registers each full citation under the short forms it could later be referred to by (any short form the drafter declared in quotes, plus the shortened case names a drafter plausibly uses), and resolves later references back to it. A footnote is split on `;` first, so one authority in a multi-authority footnote can never take the next one's pinpoint.
- A short form that matches more than one authority is never guessed at. It is reported as unresolved and no source is fetched for it — a wrong citation shown with full confidence is worse than a flagged gap. Only a `resolved` citation ever carries an identifier; everything else keeps its candidates separate, so nothing downstream can fetch on the strength of a guess.
- The reviewer resolves those cases in the pane. An ambiguous reference offers its candidates; a reference matching nothing offers every authority the document itself establishes; a name Ibid only recognises from its frequently-cited-cases list is offered as a suggestion to confirm rather than presented as established, since that is outside knowledge rather than something the document said. Confirming applies to that short form for the rest of the document, and is never carried into another document.
- Confirmation is asked for only where Ibid genuinely does not know. Prompting on every citation would make the prompt a reflex rather than a decision, and would end up laundering guesses as human sign-off. Instead every resolved citation states how it was resolved — from a short form the document defines, inferred from a case name cited in full earlier, or confirmed by the reviewer — so the reviewer can see what to check without being asked to click through what is not in doubt.
- Back-references — `Ibid.`, `Id.`, `Ibidem`, `supra note 4` — are resolved to the authority they point at, including through a chain of them. Where the text pointed at established exactly one authority these are not guesses to be confirmed but statements of what the word means, so they resolve outright and say where they read it: "Read as the authority cited immediately before it, in footnote 12." A bare `Ibid.` repeats the pinpoint as well as the authority; `Ibid., para. 44` keeps the authority and states a new one. Where the text pointed at cites several authorities, the reference is reported ambiguous with its candidates ordered nearest-cited first — the conventional reading offered as a hint, never applied. A back-reference never points at an authority the document did not itself establish, so it cannot inherit a suggestion or a guess, and confirming one applies to that single reference rather than to every `Ibid.` in the document, since each means whatever precedes it.
- Pinpoints are parsed as lists, not single numbers: `paras 40–44, 46 and 48` and `§§ 40-44, 46` report every paragraph cited, while the source lookup still narrows to the first.
- Citations are normalised to CELEX where derivation is reliable, such as `C-293/12` → `62012CJ0293`, `Regulation (EU) 2016/679` → `32016R0679`, and `Article 101 TFEU` → `12016E101` (individual treaty articles carry their own dedicated CELEX, distinct from the whole-treaty document). Case numbers are recognised with the non-breaking hyphen CURIA's own documents use and with their procedural suffix (`C-550/07 P`, `T-286/09 RENV`).
- The local API retrieves a bounded official EUR-Lex/CELLAR passage and focuses on the cited point or Article, across older (2010s-and-earlier, `text/html`-only) and newer (`application/xhtml+xml`) legislation formats, and across four distinct judgment paragraph-numbering conventions spanning the 1990s to 2025 — all confirmed live against real documents, including a real client document that surfaced most of this. A citation like "Art. 8(5)" narrows all the way to just paragraph 5 of Article 8, not the whole article, across both legislation markup eras. It has configurable authentication headers, timeout, cache, retry/backoff, and request spacing. It also verifies a response is a genuine CELLAR document before showing it — anonymous access was observed live serving a bot-verification page with an ordinary `HTTP 200`, which would otherwise be decoded and shown as if it were the source text.
- CJEU/General Court case citations get the same treatment: when a citation is confidently the main judgment, the API fetches the actual judgment text from EUR-Lex/CELLAR (which mirrors CJEU case law under its own CELEX) and focuses it on the cited point — the lawyer reads the real paragraph inline instead of following a search link. Advocate General opinions and orders are retrieved the same way: the CELEX sector is derived from the document type (`CC` for an opinion, `CO`/`TO` for an order), so the lawyer reads the opinion itself rather than a link to the case record. An opinion citing no case number takes it from the judgment the document cites elsewhere. Any fetch failure falls back to the official CURIA link, which stays the floor for documents CELLAR does not mirror. Commission references still use a direct-official-record adapter, avoiding unreliable scraping of search result pages.
- The Word pane displays loading, success, empty, unconfirmed, and retrieval-error states. A confirmed citation always exposes the official source link; an unconfirmed one shows its candidate authorities instead and does not offer a source, since Ibid does not know which document it would be showing.

## Development
Run `npm run dev` from the repository root. This builds and starts the local resolver and Vite task-pane server. If port 4000 is occupied, use `IBID_API_PORT=4001 npm run dev` so both the API and Vite proxy use the same alternate port.

Run `npm run verify` to lint, type-check the tests, run the 312 tests, and build.

For the detailed implementation handoff and test checklist, see [HANDOFF.md](HANDOFF.md).

## Production hardening
- Provision authorised EUR-Lex/CELLAR access and configure the server-side environment variables described in `api/README.md`. Anonymous access was observed live being served a bot-verification page under normal-seeming request volume — authorised access is not just a courtesy, it is likely necessary for reliability. See HANDOFF.md for what was directly observed.
- Split the Commission adapter by decision family once citation metadata identifies competition, state-aid, merger, or infringement registers.
