What Crosses the Wire

What the add-in reads inside a Word document, how it retrieves an official source, and what never leaves the workstation.

§1

What the add-in analyses

Ibid is a reading aid. It identifies references to EU law in footnotes — ECLI identifiers, Court of Justice and General Court case numbers, directives, regulations, Treaty articles, DG Competition case numbers — and displays the corresponding official passage alongside them.

It reads the full text of the open document, and we state that plainly rather than let you infer that it only touches footnotes. Two things make it necessary.

First, short-form citations mean nothing in isolation. A footnote reading “Akzo Nobel, para. 40” carries no information on its own; it only means something relative to a full citation stated earlier. Ibid therefore reads the document in order so it can resolve each later reference back to the authority it points at. Second, the pane follows the cursor: putting the caret on a reference mark brings up that citation’s source, which requires knowing where the caret is in the body.

That reading happens in memory, inside Word’s embedded browser (WebView2 on Windows, WKWebView on macOS). The recognition module is compiled into the pane’s own JavaScript bundle and executes on the workstation. Detecting citations, resolving short forms, following chains of back-references — Ibid., supra — and deriving the CELEX identifier: the whole of that chain is local and issues no request.

§3

How it retrieves the source

Once a citation has been recognised and normalised locally, the pane holds an official identifier — the CELEX number, the public nomenclature of the EU Publications Office. Fetching the text is then a matter of requesting a public document by its number.

That happens through a single request, issued from a single line of code, and only when the reviewer selects a citation:

# addin/src/ui/App.tsx — the pane's only network call
GET {ibid-origin}/api/sources?lookup={…}

The lookup object contains these fields and nothing else.

FieldExampleWhat it is
sourcecuriaWhich database to query
valueC-293/12The citation as written in the footnote
celex62012CJ0293Official EU identifier
ecliECLI:EU:C:2014:238European Case Law Identifier
caseNumberC-293/12Case number
caseNameDigital Rights IrelandPublished case name
documentTypejudgmentJudgment, opinion or order
locator{ kind: 'point', start: 40 }The point cited
paragraphs[40]Every paragraph cited

The server then requests the document from the Publications Office by that identifier, extracts the passage matching the cited point, and returns it. At no stage does it know which document the citation came from.

Stated precisely, because a reviewer will check

Two of these fields are substrings of the footnote: value, the citation exactly as written, and caseName, the case name where one is recognised. Those are the reference itself — the thing being looked up — and no query can happen without them. What never crosses the boundary is everything around the citation: the sentence carrying it, the argument it supports, the rest of the footnote, the rest of the document.

§4

What never crosses, and why that is structural

The document
The footnote as written
The citation’s context
The file name
The user’s identity
Anything about the matter

The exclusion is not incidental. It is guaranteed by the way the request is built — and it is the point we would invite your team to verify first.

The object handed to the lookup function is a CitationContext, defined as CitationMatch & { context: string }. In other words: the surrounding prose is present on the object, in memory, at the moment the request is formed. A single object spread would have sent it along with everything else.

Instead the request is assembled by naming its nine fields one at a time, with no spread operator. The consequence is durable: a developer who adds a field to the citation type tomorrow cannot cause it to start crossing the wire by accident — they would have to type it into the lookup explicitly. That is the difference between “context is not sent today” and “context is not sent.”

§5

Permissions, storage, retention

Word permission. The manifest declares ReadDocument, read-only. No write call — insertText, insertParagraph, insertHtml, insertOoxml — appears anywhere in the pane’s source. The add-in is structurally incapable of altering a document.

Accounts. None. No authentication, no sign-in, no user identifier of any kind.

Client-side storage. The pane uses neither localStorage nor sessionStorage, and sets no cookies.

Server-side storage. An in-memory cache of retrieved passages, lost when the process restarts. Nothing is written to disk: the server contains no file-write call at all. See point 3 in §7 — that cache is currently unbounded.

Logging. The server logs its own startup and startup failures. It does not log requests.

Telemetry. None. No analytics, no error reporting, no advertising, and no fonts or scripts served from any third-party CDN.

§7

Six points we put to you ourselves

A note like this is only worth reading if it also flags what deserves discussion. There are six, and we would rather raise them than have you find them. None concerns the handling of document content — that analysis never leaves the pane. All six are properties of how the service is deployed and operated, and the first two are why the hosting decision matters.

Point 1 — The service authenticates nothing

The API performs no authentication of any kind: no key, no session, no allowlist. It binds to 127.0.0.1, but the reverse-proxy configuration we ourselves recommend then publishes /api/* from a public hostname. Anyone who learns that hostname can issue lookups.

They cannot reach the document, which never leaves the pane, and they cannot redirect the outbound fetch — see “What untrusted input can reach” below. They can consume the service and cause requests to publications.europa.eu carrying the operator’s User-Agent. Before production use, place the API behind the firm’s network boundary, a shared secret, or an authenticating proxy. The CORS header is not a control here: Access-Control-Allow-Origin constrains browsers, not curl.

Point 2 — Request throttling is global, not per-caller

The resolver spaces its outbound requests through a single shared queue, by default one per second. That is a politeness limit toward EUR-Lex, not a defence: it is shared by every caller, so one client issuing continuous lookups delays everyone else’s behind it. Together with point 1, an unauthenticated public deployment can be rendered unusable by a single script. Per-IP rate limiting belongs at the proxy.

Point 3 — The retrieved-passage cache is unbounded

Previews are held in memory with no size limit and no expiry, and part of the cache key is supplied by the caller. Growth is slow — an entry is stored only after a successful upstream fetch, which the throttle caps at roughly one per second — and the cache holds public EU legal text, never client material. But it is unbounded in a process intended to run for months. Restarting the process is today’s mitigation; a bounded LRU is the fix.

Point 4 — The pane declares no Content-Security-Policy

The task pane ships without one. Nothing in it writes markup to the DOM: there is no dangerouslySetInnerHTML, innerHTML, eval or srcdoc anywhere in the pane or the shared module, and retrieved passages are rendered as React text nodes and therefore escaped. So there is no known injection path for a policy to close — this is defence in depth that is currently absent, not an open hole.

Point 5 — Reverse-proxy access logs

The lookup travels in the query string of a GET. Any reverse proxy or load balancer placed in front of the service — Caddy, nginx — will therefore record it in its access log by default. The application logs nothing; the infrastructure might. Two remedies, either of which works: disable access logging on the /api route, or change the endpoint to accept POST. We are glad to make that change if you would prefer it.

Point 6 — A lookup is still intelligence

Ibid does not transmit client material. It does transmit which authorities are being researched, and when, to whichever host runs the service. That is not privileged content, but it is not nothing either — and it is precisely the fact on which the hosting decision should turn.

What untrusted input can reach

Point 1 means untrusted input can reach the resolver, so the natural next question is what that input can make the server fetch. The answer is: only a CELEX document on the configured host. The outbound URL is the fixed base URL plus the percent-encoded identifier, so a caller cannot introduce a separator, leave the path segment, change the host, or append a query. The base URL comes from environment configuration, never from the request.

Smaller items, for completeness

API responses do not set X-Content-Type-Options: nosniff; every response is application/json and the pane does not interpret them as anything else. On an upstream failure the server returns the underlying error message to the caller, which can name the upstream host and HTTP status — it carries no request data.

What follows from those points: where to host

Recommended
Inside the firm’s infrastructure

Nothing leaves the firm’s control except the onward query to a public legal database. The server is a single Node process with no dependencies and no persistent state.

Evaluation
Hosted externally

Appropriate for an evaluation period, provided the service stays stateless, access logging is switched off, and access is restricted per point 1.

Theoretical
On the reviewer’s machine

Nothing leaves at all, but it requires Node and a locally trusted certificate — generally impractical on a managed device.

§8

Verify rather than take our word

Every claim in this note is checkable against the repository. These commands produce exactly the result stated beside them.

# One outbound request in the pane, and no browser storage.
# Expected: a single hit, in App.tsx.
grep -rn "fetch(\|XMLHttpRequest\|sendBeacon\|WebSocket\|localStorage\|sessionStorage" addin/src/ shared/src/

# The add-in cannot write to the document. Expected: no hits.
grep -rn "insertText\|insertParagraph\|insertHtml\|insertOoxml" addin/src/

# Read-only permission. Expected: <Permissions>ReadDocument</Permissions>
grep -n "Permissions" addin/manifest.xml

# Exactly what is put on the wire: nine named fields, no spread.
sed -n '/const lookup = {/,/};/p' addin/src/ui/App.tsx

# Nothing is written to disk, anywhere in the server. Expected: no hits.
grep -rn "node:fs\|writeFile\|createWriteStream\|appendFile" api/src/ api/server.mjs

# The server logs startup only, never requests.
grep -n "console\." api/server.mjs

# Runtime supply chain: none for the API, react + react-dom for the pane.
grep -A4 '"dependencies"' api/package.json addin/package.json

# Dependency advisories, runtime and build-time.
